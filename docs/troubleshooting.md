# Неполадки

## Не устанавливается

**Google Play Защита блокирует установку из файла.** Приложение не из магазина и подписано отладочным ключом.
Варианты: установить через `adb install` (Защиту трогать не нужно) или временно отключить Защиту
в Play Маркете → профиль → Play Защита. После установки Защиту можно включить обратно; если она предложит
удалить приложение, выберите «Не удалять».

**Samsung Автоблокировщик.** Настройки → Безопасность и конфиденциальность → Автоблокировщик блокирует
приложения не из магазина. На время установки выключите.

## Служба не включается

Сообщение «Доступ для приложения запрещён» / «Ограниченная настройка»: Android 13+ не даёт сразу включить
специальные возможности приложению, установленному из файла.

1. Один раз попробуйте включить службу (без этого пункт ниже не появится).
2. Настройки → Приложения → **Meet Captions** → ⋮ справа вверху → **Разрешить ограниченные настройки**.
3. Снова Специальные возможности → Установленные приложения → Meet Captions → вкл.

Если пункта в ⋮ нет — переустановите через `adb`: такие установки не помечаются ограниченными.

```bash
adb uninstall dev.octrow.meetcaptions
adb install app-debug.apk
```

## Файла после звонка нет

Проверьте по порядку:

1. Служба включена: Специальные возможности → Meet Captions → вкл. После `adb install -r` она остаётся включённой.
2. Батарея → **Без ограничений** для Meet Captions.
3. В звонке включены субтитры и кто-то говорил. Без речи субтитров нет.
4. Экран звонка был открыт. В свёрнутом звонке (вкладка Meet в Gmail, мини-окно) субтитров на экране нет.
5. Звонок идёт в поддерживаемом пакете: `com.google.android.gm` (Gmail) или `com.google.android.apps.tachyon` (Meet).
   Текущий пакет звонка видно так:
   ```bash
   adb shell dumpsys activity activities | grep -m1 topResumedActivity
   ```
   Другой пакет — добавить его в `MEET_PACKAGES` (`CaptionService.kt`) и `android:packageNames`
   (`res/xml/accessibility_service.xml`).

Если всё так, а файлов нет даже в режиме отладки (нет `events_*.txt`), служба не получает событий:
см. `isAccessibilityTool` в [decisions.md](decisions.md).

## Вместо имён `?` или текст слипся с именем

Meet изменил формат субтитров. Включите отладку и разберите дампы (ниже).

## Meet обновился и запись пропала

1. Meet Captions → включите **«Отладка»**.
2. Звонок, субтитры, минута-две речи с двух устройств. Выключите отладку.
3. Заберите файлы:
   ```bash
   adb pull /sdcard/Documents/MeetCaptions/
   ```
   - `events_*.txt` — каждое событие Meet: время, тип, класс, id источника, текст.
   - `dump_*.txt` раз в 5 с — все окна на экране (у чужих только заголовок) и полное дерево окон Meet.
4. Найдите строку с текстом субтитров:
   ```bash
   grep -h 'text=.*[а-я]' dump_*.txt | grep -v 'text=null' | sort -u
   grep -h src= events_*.txt | grep -o 'src=[^ ]*' | sort | uniq -c | sort -rn
   ```
   Источник, который обновляется чаще всех во время речи, обычно и есть субтитры.
5. Впишите часть его id в поле «Regex id текста субтитров» → «Сохранить regex». Если имя в отдельном узле —
   его id в «Regex id имени говорящего».
6. Если у узла субтитров `id=null` (Compose без resource id), regex не поможет: нужен другой селектор в коде.

Удалите дампы после разбора: в них e-mail аккаунта и имена участников.

## Звонок разрезан на два файла

Субтитров не было больше 5 минут (тишина, демонстрация экрана). Константа `SESSION_GAP_MS` в `CaptionService.kt`.

## Задвоенные строки в файле

Склейка не нашла продолжения: Meet исправил одно из первых трёх слов реплики. Если случается часто,
пришлите фрагмент файла и снимки из `dump_*.txt` — по ним добавляется тест в `CaptionMergerTest`.
